# Candidate Outlet Exploration

Updated: 2026-06-11

Status: provisional evidence package. No boundary is accepted.

## Purpose

This note records the first data-driven candidate outlet and catchment discovery run for the
Zimbabwe / Upper Mzingwane prototype. It implements a staged exploration approach: use existing
local HydroBASINS and Zimbabwe Geoportal boundary data first, then add river, flood, mining, and
DEM evidence only where needed.

The output is not a flood-risk map, intervention-priority map, or final thesis boundary. It is a
ranked candidate package for mentor or domain review.

## Execution

- Tooling scripts:
  - `bin/discover_candidate_outlets.py`: generate candidate outlets, catchments, scoring, and
    GeoPackage layers.
  - `bin/export_candidate_topology.py`: generate topology helper CSV and GeoPackage layers for
    explaining `target -> NEXT_DOWN`.
  - `bin/plot_candidate_outlets.py`: render diagnostic PNG/PDF figures from the generated
    GeoPackage and topology CSV.
- Python environment: root `.venv/`, created with Python 3.12 and local GIS packages
  (`geopandas`, `pyogrio`, `shapely`, `pyproj`, `pandas`, `matplotlib`).
- Command:

```bash
.venv/bin/python bin/discover_candidate_outlets.py
.venv/bin/python bin/export_candidate_topology.py
.venv/bin/python bin/plot_candidate_outlets.py
```

## Candidate Logic

The search frame combines:

- Geoportal `Upper Mzingwane` as the broad local named envelope;
- HydroBASINS level 7 `HYBAS_ID=1071528840`, `PFAF_ID=1245086` as the hydrological reference;
- a 10 km metric buffer around the union for diagnostic display only.

Candidate outlets are approximated from HydroBASINS topology by using each target unit's
`NEXT_DOWN` relation and selecting a shared-boundary midpoint where possible. Candidate
catchments are generated by tracing upstream units at the same HydroBASINS level and dissolving
all units whose downstream chain reaches the target unit.

Approximate anchor checks use Mzingwane Dam, Esigodini, Gwanda, Filabusi, and West Nicholson
screening points. Filabusi and West Nicholson are approximate screening anchors only, not
validation data.

## Superseded Machine-Prior Recommendation

The first script-first run ranked `HB_L8_1081522660_literature_near` as C1. This is now
superseded as a recommendation after the 2026-06-12 mentor reply, which emphasized a Level-8
basin containing Mzingwane Dam and the main Mzingwane River channel downstream toward Gwanda.

C1 should now be treated only as a machine-derived topology prior, not as the primary outlet
recommendation.

Original machine-prior rationale:

- It is generated from reproducible HydroBASINS topology.
- Its upstream union contains the current Mzingwane Dam and Esigodini anchors.
- It excludes the Gwanda contrast anchor.
- It is much smaller than the `~3700 km2` L7 candidate and `~7321.5 km2` Geoportal named feature.
- Its area is still below the literature `~2138 km2` value, so it must not be presented as a
  recovered literature boundary.

The professional map review now carries forward:

- V1 / `HB_L8_1081528840_full_l7_chain` as the primary mentor-review candidate;
- V2 / `HB_L8_1081528170_broader_nested` as an upstream alternative;
- V3 / `HB_L8_1081522660_literature_near` as the demoted C1 machine prior.

See `context/docs/project-management/professional_map_outlet_review_2026-06-12.md`.

## How To Read The Diagnostic Figures

Use a programming mental model:

```text
HydroBASINS polygon = graph node
NEXT_DOWN = directed edge to the downstream node
candidate catchment = all nodes that eventually flow into the target node
outlet proxy = boundary point between the target node and its NEXT_DOWN node
```

Figure guide:

- `diagnostic_map_explained.png`: overview for non-GIS readers. It shows C1-C7 outlet proxies,
  candidate upstream catchments, the broad Geoportal context boundary, screening anchors, and the
  top-ranked candidates.
- `diagnostic_c1_flow_explainer.png`: explains why C1 is called an outlet proxy. Light blue is
  the C1 upstream catchment, dark blue is target basin `1081522660`, gray is downstream basin
  `1081528170`, the purple point is the outlet proxy, and the red arrow shows
  `target -> NEXT_DOWN`.
- `diagnostic_topology_table.png`: tabular view of every candidate's `target_id -> NEXT_DOWN`
  edge, area, anchors, score, and status.

Important interpretation rule:

The C-points are outlet proxies generated from HydroBASINS topology. They are not measured river
outlets, DEM-derived pour points, or mentor-accepted flood/mining impact points.

## Data Gaps

The first run has no direct river-line, flood-zone, mining-footprint, or DEM-derived flow
accumulation evidence. Because of this, the `flood/mining relevance` score is capped and based
only on screening anchors.

Next evidence sources to add only if needed:

- HydroBASINS pour points for official sub-basin outlet points.
- HydroRIVERS for river-network plausibility and river-exit checks.
- Zimbabwe Geoportal Rivers and Flood Prone Zones for local river and flood-impact evidence.
- OSM / Geofabrik Zimbabwe for roads, bridges, settlements, and mine/quarry tags.
- Copernicus DEM or SRTM only if an independent DEM delineation is required.
